# 專案管理報告匯出成 Markdown（Issue #307）

指令 **Multiagent: Export Project Report (Markdown)**（命令面板，或 Command Center 的 **Export report…** 按鈕）把目前的專案狀況彙整成一份 Markdown，方便查看。

## 內容

- **摘要**：本機 `origin/main` 的 head（上次 fetch 的結果，不連線）、開啟中的 Issues／PRs 數量。
- **開啟中的 Issues**：需求（第一段）、驗收進度（Issue 內 `驗收`／`Acceptance` 底下勾選了幾項；沒有勾選框時明說「不在 Issue 裡追蹤」）、對應的 PR。
- **開啟中的 PRs**：head、PM 報告狀態（對這個 head 是否最新）、最新 head 上的正式審查與 CI、未解決討論串、你可以做什麼／下一步、目前在哪一類（待決策／要求修改／已通過）。
- **待決策事項**：待決策或待補證據的 PR 與 Issue 數。
- **Agents**：每個 session 的角色、供應商、狀態與依據、任務、工作資料夾的 Git 讀數、額度摘要、警示；帳號以編號列出（不顯示標籤）。
- **最近的廣播**（最多 10 則）與送達結果。
- 最後一節說明這份報告不知道什麼。

## 怎麼開啟與保存

- 以**未儲存的編輯器**開啟，不綁定任何檔案；預設**不會**寫入工作區或儲存庫。要保存請自己用 Save As。
- 指令不接受任何參數；在未信任的工作區不能用。

## 遮罩與防偽

- 讀不到的來源在自己的位置寫 `unknown（原因）`，不會省略、也不會寫成 0。
- GitHub 的標題／內文、session 名稱、廣播文字都是**純文字欄位**：移除控制／方向／不可見字元、限制長度、Markdown 特殊字元全部跳脫，所以不能變成標題、連結、表格、程式碼區塊或 HTML；報告裡所有標題都是本程式產生的。
- 每個欄位都用與發佈前相同的掃描檢查（憑證、本機路徑、email 等）；看起來是私人資料的欄位會被換成 `(withheld: looked private)`，其他內容照常。掃描無法完整進行時整份報告不產生。組好的整份文件會再掃一次。
- 帳號標籤、session id 不會出現在報告中。

## 限制

- 同一份資料不保證是同一個時間點；審查與 CI 只對旁邊寫的那個 head 有意義。
- 最多列出 100 個 Issue、100 個 PR（其中最多 30 個會讀取審查細節，其餘寫 unknown）、60 個 agent，超過的會標示還有幾個。
- 掃描是形狀偵測，看不出改寫過的私人資訊；保存或分享前請自己再看一次。
- 尚未用真的帳號與 GitHub 專案實際驗證（#135）。
