# GitHub 留言的作者（#342）

管理者和所有 agent 共用同一個 GitHub 帳號，而且 repo 是公開的。所以 GitHub 顯示的帳號名稱說明不了是誰寫的，沒有署名的留言也不能當成管理者寫的。報告頁依下面的順序判斷每則留言與 review 的作者：

1. **管理者**：你在 VS Code 從報告頁發出的留言（Publish public feedback）或正式 review（Review pull request），在 GitHub 確認發出後，擴充套件會把 GitHub 給的 ID，以及這段內文的 SHA-256，記在私人儲存區（`ownerPosts`）。只有 ID 在這份紀錄裡、**而且**目前的內文和當時完全相同時，才顯示為「管理者」。
2. **管理者發的留言，但之後被修改過，無法確認作者**：ID 在紀錄裡，但內文已經和當時不同。帳號是共用的，任何 agent 都能改寫你的留言（例如 `gh pr comment --edit-last`，或用 curl 送 PATCH），所以改過的內容一律不當成你的。在加入內文 hash 之前留下的紀錄沒有 hash 可以比對，顯示為「舊紀錄（沒有內文雜湊），無法驗證是不是管理者」。
3. **`Worker-01（自稱）`**：第一行是 agent 的署名（`— Worker-01`）。判斷方式和 agent 終端機的 `gh` 包裝程式相同：看不見的字元先移除，各種 Unicode 破折號視為 `—`。這是 agent 自己寫的，不是證明。`Admin-01`、`Owner-01` 這類看起來像負責人的代號，擴充套件從來不會發，所以算未署名。
4. **未署名**：以上都不是。
   - 私人儲存區讀不到時，顯示「未署名（讀不到管理者的留言紀錄，無法確認是不是管理者）」，不會猜。
   - 行內 review 留言（inline）不能從 VS Code 發，所以永遠不會顯示為管理者。

每一行後面的 `[GitHub 帳號]` 是 GitHub 上的帳號名稱，只是附帶資訊。

## 紀錄的細節

- 每個 repo 一份紀錄，repo 名稱不分大小寫。留言與 review 各保留最新的 5000 筆。被刪掉的較舊紀錄，那則留言會改顯示為「未署名」，絕不會顯示成 agent。
- 紀錄存在但讀不懂時，回報錯誤，不會當成空的，也不會被覆寫。
- 留言已經發到 GitHub、但 ID 寫不進紀錄時，留言不會被收回。畫面會告訴你這件事，報告頁會把它顯示為「未署名」，不會顯示為管理者。
- 同一則留言重送時（already sent），不會再發一次，也不會改動紀錄。

## 擴充套件代 PM 發的內容

目前報告頁的每一個發佈動作（留言、正式 review、合併、刪分支、關 Issue）都要由你在 VS Code 確認後才執行，所以它們都是管理者發的，不加署名。擴充套件目前沒有「代 PM agent 自動發到 GitHub」的路徑。agent 自己發的內容，由 agent 終端機的 `gh` 包裝程式補上署名。

## 限制

- 署名是自稱的：agent 可以用 curl，或用絕對路徑呼叫真正的 gh，繞過包裝程式。所以只有留言 ID 紀錄能證明是管理者。
- 「Pass／Needs changes」判定的解讀規則沒有改變：仍依 GitHub 帳號判斷是不是 repo 擁有者。因為帳號是共用的，這個判定也只是 GitHub 上的文字；正式的合併條件見合併流程的檢查。
