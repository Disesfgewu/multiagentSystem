# Start Meeting（Issue #308，第三部分）

指令 **Multiagent: Start Meeting**（命令面板，或 Command Center 的 **Start meeting…**）：輸入一個主題、勾選至少兩個有開著終端機的 agent，確認後把同一個主題以單行 prompt 同時打進這些 agent 的終端機，之後整理成一份會議紀錄（Markdown，未儲存的編輯器）。

## 送出
- 與其他「打進終端機」的指令共用同一個確認與判斷（`confirmAndType`）：確認視窗顯示完整 prompt 與名單；只有 CLI 自己說在等輸入的才送，狀態不明要按第二個明確按鈕，忙碌／結束／終端機已關的不送並說明原因；確認後再檢查一次，主題變了不送；結果記在派發紀錄（kind: meeting，不存主題文字）。
- 主題先檢查：隱藏／方向字元、本套件自己的標記字樣（含 `Meeting topic from the administrator`）、「忽略規則」類文字、憑證／本機路徑／email 都會被拒絕（不是清掉）。主題包在 `«…»`，prompt 說明它是資料。
- 指令不接受參數；未信任的工作區不能用。

## 回覆與會議紀錄
- **本擴充套件讀不到 agent 的回覆**（沒有可靠的通道，也不去讀 CLI 的對話紀錄）。agent 在自己的終端機回答後，你選 **Enter Replies**，對每個被問到的 agent：先出現一個**非 modal** 的提示（你可以去它的終端機複製答案），按 **Read Clipboard** 才讀剪貼簿，再用 modal 顯示前 200 字讓你確認 **Record Reply**；**Escape 或關閉只略過這一位**，後面的 agent 照常輪到。
- **剪貼簿沒換**：如果同一段文字已經記給前一位 agent，會明說「與某某的回覆相同」並要求另外按 **Record It Anyway** 才記（避免把 A 的回覆記到 B 名下）；剪貼簿是空的就不記。
- 紀錄裡每個人寫明：有沒有被打進主題（沒被打進的寫原因）、回覆「由你從該 agent 的終端機貼上」。**沒貼的一律寫「no reply recorded」**；沒被問到的 agent 不會有回覆欄位內容。不會有任何替 agent 編寫的文字。
- 貼上的回覆是純文字區塊引用：移除控制／方向字元、Markdown 特殊字元跳脫、限 4000 字、每行都在引用裡，不能變成標題、連結、表格或程式碼區塊；每個欄位用發佈前同一個掃描器檢查，看起來私人的欄位換成 `(withheld: looked private)`，掃描無法完整進行就不產生紀錄，整份還會再掃一次。

## 限制
- 回覆是人工貼上的，無法證明某段文字真的出自那個 agent；紀錄只說「你貼上的」。
- 沒有用真的 CLI 驗證（#135）；host 測試用合成的 CLI。
