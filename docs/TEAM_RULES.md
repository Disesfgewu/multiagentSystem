# 團隊共同規則（Issue #306，第一階段）

一份**全體 agent 共同遵守**的規則清單，每次啟動 agent 時排在身份組規則之前一起注入。

## 怎麼用

- 命令面板：`Multiagent: Edit Team Rules`，或 Command Center 的 **Team rules…** 按鈕。
- 新增、修改、移除一則規則。每次存檔前都會有確認視窗，寫出「新增／修改／移除哪一則」與「已在執行的 agent 不會改變，只有之後啟動的才會拿到新版」。
- 規則存在私有儲存區（collection `teamRules`），不會寫進任何儲存庫。每次存檔版本 +1；兩個視窗同時改時，後存的那個會被拒絕（要重新開啟再改），不會互相覆蓋。
- 指令**不接受任何參數**：規則文字、選哪一則、確認都只來自這個視窗；Command Center 的按鈕只送一個固定訊息、不帶任何內容。

## 注入與預覽

- 團隊規則是 `user` 層的規則。規則解析器（`src/memory/rules.js`）先依層的強弱排序、同一層內再依規則 id 排序，所以團隊規則排在身份組自己的規則（`roleGroup` 層）**之前**，不論 id 的字母順序；它和身份組在 `user` 層的規則同層，彼此之間依 id 排序（團隊規則的 id 是 `team:N`），不是依清單位置。沒有身份組的 agent 也會拿到。
- 存檔前會檢查：看起來像憑證、email 或本機路徑的文字不能存成規則（規則會被打進每個 agent 的指令）。
- **Preview Effective Rules** 會顯示「Team rules (vN): …」與每一則規則的文字；讀不到時明說「unknown…NOT reflected」，不假裝已套用。
- 啟動 agent 前準備的指令快照記錄團隊規則的版本。規則在準備之後被改了，快照視為過期（`team-rules-changed`），不會用舊的啟動。
- 團隊規則**讀不到或已損毀**時，啟動被拒絕（`team-rules-unavailable`），不會悄悄少帶規則啟動。
- 規則和其他指令一樣會經過「要 agent 忽略規則」類文字的檢查；有就拒絕啟動。

## 限制（誠實說明）

- 這是**告訴** CLI 的指示，不是強制：本擴充套件不會因為規則而阻止 agent 做任何事。能擋的是身份組的工具權限（見 `docs/ROLE_GROUPS.md`）與隔離。
- 只收「指示」類規則（最多 50 則、每則 1000 字）；禁用某個工具請用身份組的工具權限。
- 已在執行的 agent 不會被改；沒有真的 Claude Code / Codex 驗證 CLI 是否讀到並遵守（#135）。

## 建議規則：小事自主決定（#362）

管理者回報：即使開了 auto mode，agent 還是常常停下來問一些不重要的問題，例如「要我繼續嗎？」「要用哪個方案？」。這是模型自己的行為，不是權限問題，所以擴充套件提供一條建議的團隊規則：

> 例行決定自行判斷並繼續，不要停下來詢問。以下情況必須先詢問管理者：無法繼續、刪除資料、force-push 或改寫歷史、合併 PR、對外發佈、花錢或使用付費額度。這條規則不取代擴充套件或 CLI 的任何確認與權限規則。

- **在哪裡加**：打開 **Edit Team Rules**（指揮台的 **Team rules…**，或 Command Palette），清單最上面會多一個選項 **Add the suggested rule: Decide routine matters yourself**。
- **要管理者同意才生效**：選了之後，會跳出和新增其他規則相同的確認視窗，並顯示完整的規則文字；按 **Save** 之後，這條規則才會加進團隊規則，之後啟動的 agent 才會收到。
- **可以修改或移除**：加入後，這條規則和其他規則一樣，可以用 **Edit a rule**、**Remove a rule** 修改或移除。
- **什麼時候會出現這個選項**：清單裡還沒有完全相同的規則時，才會出現；改寫過文字之後，原本的建議會再出現。
- 這條規則只是「告訴」CLI 的指示，擴充套件不會強制執行。它仍然要求 agent 在以下情況先詢問管理者：無法繼續、刪除資料、force-push 或改寫歷史、合併 PR、對外發佈、花錢或使用付費額度；而且明白寫出它不取代擴充套件或 CLI 的任何確認與權限規則。
