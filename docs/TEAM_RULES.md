# 團隊共同規則（Issue #306，第一階段）

一份**全體 agent 共同遵守**的規則清單，每次啟動 agent 時排在身份組規則之前一起注入。

## 怎麼用

- 命令面板：`Multiagent: Edit Team Rules`，或 Command Center 的 **Team rules…** 按鈕。
- 新增、修改、移除一則規則。每次存檔前都會有確認視窗，寫出「新增／修改／移除哪一則」與「已在執行的 agent 不會改變，只有之後啟動的才會拿到新版」。
- 規則存在私有儲存區（collection `teamRules`），不會寫進任何儲存庫。每次存檔版本 +1；兩個視窗同時改時，後存的那個會被拒絕（要重新開啟再改），不會互相覆蓋。
- 指令**不接受任何參數**：規則文字、選哪一則、確認都只來自這個視窗；Command Center 的按鈕只送一個固定訊息、不帶任何內容。

## 注入與預覽

- 團隊規則放在 `user` 層、排在身份組自己的 `user` 層規則之前；沒有身份組的 agent 也會拿到。
- **Preview Effective Rules** 會顯示「Team rules (vN): …」與每一則規則的文字；讀不到時明說「unknown…NOT reflected」，不假裝已套用。
- 啟動 agent 前準備的指令快照記錄團隊規則的版本。規則在準備之後被改了，快照視為過期（`team-rules-changed`），不會用舊的啟動。
- 團隊規則**讀不到或已損毀**時，啟動被拒絕（`team-rules-unavailable`），不會悄悄少帶規則啟動。
- 規則和其他指令一樣會經過「要 agent 忽略規則」類文字的檢查；有就拒絕啟動。

## 限制（誠實說明）

- 這是**告訴** CLI 的指示，不是強制：本擴充套件不會因為規則而阻止 agent 做任何事。能擋的是身份組的工具權限（見 `docs/ROLE_GROUPS.md`）與隔離。
- 只收「指示」類規則（最多 50 則、每則 1000 字）；禁用某個工具請用身份組的工具權限。
- 已在執行的 agent 不會被改；沒有真的 Claude Code / Codex 驗證 CLI 是否讀到並遵守（#135）。
